KnowledgeLevel: "K1: Remember"
Objective: Recognize types of work products that can be examined by static testing
Subtitle: "3.1"
---
[[Static testing]] can examine almost any work product, i.e. Requirement specification documents, source code, test plans, test cases, product backlog items, test charters, project documentation, contracts and models.

In order for [[Static testing]] To be able to examine a work product, it needs a structure against they can be checked (e.g., models, code or text with a formal syntax)
