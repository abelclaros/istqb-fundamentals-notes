[[White-box Testing]] strength - entire software implementation is taken into account during testing, it it facilitates defect detection even when the software specification is vague, outdated or incomplete
[[White-box Testing]] weakness - if the software does not implement one or more requirements, it may not detect the defects resulting from omission

[[White-box Testing]] can be used in [[Static testing]], well suited for reviewing code not yet ready for execution

Performing only [[Black-box Testing]] does not provide a measure of actual code coverage
[[White-box Testing]] focuses in coverage measures and provides confidence in the code
