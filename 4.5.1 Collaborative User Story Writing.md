[[User story]] - represents a feature that will be valuable to a user 
[[User story]] - critical aspects: Card (medium describing a user story), Conversation (explains how the software will be used), Confirmation ([[4.5.2 Acceptance Criteria]])
[[User story]] - most common format: "As a {role}, I want {goal to be accomplished}, so that I can {resulting business value for the role}", followed by the acceptance criteria

Collaboration the creation of a [[User story]] allows the team to share a common vision of what should be delivered
[[User story]] creation - takes into account: business, development, and testing

A good [[User story]] should be: Independent, Negotiable, Valuable, Estimable, Small, and Testable. (INVEST)
